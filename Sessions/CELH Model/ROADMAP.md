**Sprint rationale (2026-04-27 planning):** Several rules added during CELH+PG hardening are heuristic patches (regex on label clutter, keyword scan for "charge", allowlist of subtotal concepts, library-author-time decision on NI alias routing). These create drift risk — a future ticker could silently break CELH/PG. Sprint replaces them with structural signals (XBRL concept maps to canonical, calc-linkbase parent-of-summands, NCI presence at filing-read time) AND locks current outputs via snapshot harness so any future change against CELH+PG is mechanically detected. No new tickers added until sprint complete.

**Active propagating rule:** every structural change to the financials pipeline must update `playground_architecture.html` + `playground_schema.html`. Bump `LS_KEY` when NODES/EDGES change so the user's browser picks up fresh defaults instead of cached state. Carry this into every future handoff under "Open decisions / pending work." (User explicitly asked this rule propagate.)

**No-heuristic policy (added 2026-04-27, post Tier C sprint):** going forward, **do not introduce new label-text regexes, keyword scans, or static concept allowlists** to handle filer-specific patterns. Every routing / sign / subtotal / classification decision must be derivable from a structural signal in the filing itself — XBRL concept name, presentation linkbase, calculation linkbase, label linkbase, or a canonical declaration in `generic_line_item_mappings.json`. When a new filer breaks something, the right response is: figure out which structural signal already encodes the truth and use it. Heuristic patches accumulate drift across tickers and are exactly what the Tier C sprint replaced. Existing heuristics (`CLUTTER_RE`, `TRAILING_PAREN_RE`, walker visual heuristics like `_PRIMARY_TITLE_RE` / `_HEADER_PATTERNS`) are tolerated because their replacement is non-trivial, but they're not extended. Per `feedback_structural_over_heuristic.md`. Carry this rule into every future handoff. (User explicitly asked this rule propagate.)

**No validator sign flips (added 2026-04-27, PEP session):** validators sum line-item values as-mapped — never `-abs(value)` force-flip or any other heuristic to coerce a value into "the expected sign". Sign correctness lives at extract + library + ticker ledger (parens-negative detection, `sign_convention`, per-period tax-sign correction). PEP's FY2022 Juice Gain `(3,321)` legitimate parens-negative in the opex bucket exposed why force-flipping is wrong: it silently masks extract-layer bugs AND breaks legitimate gains-in-bucket cases. Per `feedback_no_validator_sign_flips.md`. Carry this rule into every future handoff.

**No duplicate anchor subtotals from cascade injection (added 2026-04-27, PEP session):** model-write's IS cascade-subtotal injection skips any anchor (Gross Profit / Income from Operations / Pre-Tax Income / Net Income) the filer already rendered ANYWHERE in document order — never use a windowed look-back. PEP's non-operating Juice Gain rendered between SG&A and Impairment exposed why the 4-row look-back was wrong: it observed a fake `op_exp → non_op → op_exp` pseudo-transition mid-bucket and force-injected an IFO cascade in the wrong position, scrambling the workbook layout via the by-canonical-label dedup. Per `feedback_no_duplicate_anchor_subtotals.md`. Carry this rule into every future handoff.
